# Introduction

### Welcome.

At first thanks for wanting to help microwiki, this file is a guidelines/rules to contribute project.

### Why should i follow this rules.

This rules can make communication beetween developers easier and other features like:
- Make PR checking faster and easier.
- Protect old features of braking when making new features.

### What kind of contribution are welcome:

- Repporting about bugs and offering features that will make using microwiki more comfortable, fast and easy.

- Improving documentation.

- Fixing bugs and optimizing code.



# Basic rules
### Expectations behaviour:

**Responsibilities**
- Ensure that code builds and runs on Windows and Linux without compatibility issues.
- Ensure that code passes all basic tests without errors.
- Add files with functions/classes for writing, creating and parsing configs, wiki headers, files etc to /src/microwiki/utils directory, not into /src/microwiki/.
- Welcome newcomer's and be friendly.

### How to report about bug:

Open issue ticket with 'bug' label and report about following facts:
- 1. Your OS and version.
- 2. What the bug is about.
- 3. Step to reproduce.
- 4. Version of python, textual and rich you are using(fill only if you are running without building via "make run").
- 5. Any extra notes(if there are).

### How to make a feature request:

Open issue ticket with 'enchancement' label and write about:
- 1. What the feature os about.
- 2. Why should it be add.
- 3. Any extra notes(if there are).

### How to make a pull request:

Open pull request with 'enchancement' label and write about:
- 1. Improvements/fixes made to project.
- 2. Why should it be add.
- 3. The code itself.
- 4. Any extra notes(if there are)
